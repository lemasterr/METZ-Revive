# METZ Revive — правила проекта

## Область и порядок работы

- Отвечать на русском. Стабильность, измерения и восстановление важнее максимальной производительности.
- Использовать существующий checkout. Сохранять чужие изменения. Ветки Codex: `codex/…`.
- Текущий объём: диагностика, подготовка отката и этап производительности после согласованной замены браузера. Пользователь 2026-10-09 сообщил о выполненной ручной проверке и поручил перейти к следующим этапам. Kick сохранить. Адресные изменения и UI-тесты требуют отдельного согласования.
- До диагностики и подготовки отката не модифицировать телевизор. Не создавать заглушки будущих приложений.
- Для объяснения или анализа только исследовать и сообщать результат; реализация нужна по запросу изменения.
- Применять `obsidian-projects` для проектной памяти, разрешая проект по cwd. Локальная привязка в `.codex-project.json` не публикуется.
- Делегировать только по явному запросу пользователя или обязательному workflow. Graphify использовать только для запрошенной работы с графом.

## ADB и физическое устройство

- Сначала `adb devices -l`. Каждая команда телевизору должна иметь явный `-s` с текущим адресом/идентификатором, предоставленным локально.
- Проверять состояние `device`. При ошибке подключения определить причину, ждать 60 секунд между попытками; максимум три попытки за цикл, затем остановиться.
- При `unauthorized` дать пользователю возможность подтвердить подключение. Не удалять ключи и не сбрасывать авторизацию.
- Не отключать USB Debugging. Сохранять сеть, ADB, ввод, штатный HOME и резервное управление USB-клавиатурой.
- Диагностика последовательная, ограниченная по времени и объёму; анализировать данные на Mac. Не создавать файлы на ТВ.
- Не очищать logcat. Не запускать bugreport, benchmarks, циклы питания или постоянный мониторинг без обоснования и нужного согласия.
- Отказы доступа и отсутствующие данные фиксировать; не обходить SELinux и не использовать root ради диагностических показателей.

## Согласование

- Безопасные локальные изменения и проверки без UI выполнять автономно в разрешённом объёме.
- Согласие непосредственно перед удалением/отключением пакетов, изменением настроек, установкой APK, перезагрузкой, reset, root, прошивкой и стресс-тестом.
- Пользователь 2026-10-09 разрешил обоснованные обратимые изменения пачками при наличии точного отката и сохранении загрузки/управления ТВ. Применение и возврат согласованной пачки не пересогласовывать по каждому пакету. Это не разрешение на root, reset, firmware/bootloader, непроверяемый откат или неназванные UI-тесты.
- Не менять напряжения, частоты сверх штатных, загрузчик и системные разделы; не ослаблять защиту и thermal protection.
- UI/browser/device-тесты, ввод команд управления и автоматизированные screenshots требуют отдельного разрешения. Диагностика ADB чтением не является разрешением управлять интерфейсом.
- Пользователь 2026-10-09 разрешил push и создание PR в `lemasterr/METZ-Revive` без повторного подтверждения. Перед отправкой всё равно проверить branch/remote/base/commit и приватность. Это разрешение не распространяется на merge, релизы, сообщения и изменения ТВ.
- Другие внешние/необратимые действия требуют отдельного конкретного согласия непосредственно перед записью.
- Не устанавливать инструменты, зависимости, skills и плагины без явного разрешения на конкретную установку.
- Существенные изменения: причина → исходное состояние → план отката → согласие → изменение → проверка → запись результата.
- Объединять независимые обоснованные изменения текущего этапа в пачку; сначала сохранить исходное состояние всей пачки, затем применить последовательно и проверить общий результат. При частичном отказе вернуть уже применённую часть.

## Приватность и отчёты

- Не читать целиком `.env`. Не раскрывать секреты, ключи ADB, токены, cookies и личные данные.
- Raw-снимки хранить только в игнорируемом `local/` с ограниченными правами. Не публиковать адреса LAN, SSID/BSSID, MAC, серийные номера, пользовательские пути, raw-логи и APK.
- В Git включать только проверенные очищенные документы и исходники. Не применять `git add -A` к смешанному worktree.
- Для проблемы указывать доказательства, причину, уверенность, влияние, решение, риски, откат и приоритет.
- Отделять подтверждённый факт, гипотезу, сообщение пользователя и непроведённую проверку. Отсутствие ошибки в короткой выборке не доказывает исправность.
- В конце этапа дать статус дорожной карты: выполнено, текущая работа и незавершённые проверки, цель следующего шага и следующие этапы. Не выдавать план за применённую оптимизацию.
- Не выводить энергопотребление из CPU и не подменять физическое разрешение панели размером Android framebuffer.

## Архитектура и проверка

- Диагностика: ADB, Python standard library, Shell. Минимум зависимостей, фоновых процессов и временных файлов.
- Будущие METZ Home: Kotlin + Android Views; тёмный однотонный фон, без рекламы, тяжёлых анимаций, постоянного сканирования и сетевых запросов.
- METZ Casting: потоковая передача без постоянного сохранения медиа; сначала штатный Cast, затем обоснованная архитектура. Не устанавливать рекламные сторонние приёмники.
- METZ Manager: Swift/SwiftUI, нативные macOS API; без Electron и облачного backend без необходимости.
- После изменения запускать релевантные доступные проверки. UI-валидацию без согласия отмечать как не проведённую.
- Не разрабатывать AI, умный дом, пульт iPhone, игровые функции и тяжёлые заставки в текущем объёме.
