# METZ Manager 0.2.0 — этап 9

Небольшое нативное SwiftUI/AppKit-приложение для Mac. В 0.2.0 к сбору диагностики добавлены история и сравнение локальных снимков. Этап 9 продолжается независимо от отложенной ручной приёмки Home/Cast/скорости.

## Что работает в коде

- Выбор существующего checkout METZ Revive; путь сохраняется только в локальных UserDefaults.
- Обновление списка `adb devices -l` по кнопке, явный выбор serial. `unauthorized`/`offline` видны, сбор для них запрещён. Автоподключения, сброс ключей и reconnect нет.
- Снимки audio/cast/remote/video через существующий `scripts/collect_diagnostics.py`, по одному запросу за раз. Скрипт повторно проверяет состояние `device`, каждая команда имеет `-s` и ограничение 20 секунд/256 КиБ. Для звука добавлены foreground и фиксированный список vendor sound keys, только чтением.
- Краткая сводка на Mac: завершение команд/ограничения, доступная Android RAM, наличие активной аудиодорожки и mixer underruns. Raw-логи и секреты в интерфейс не выводятся. Ошибка shell, timeout, truncation и stderr отражаются как ограничения, а не успех.
- Raw хранится в игнорируемом `local/diagnostics` с правами сборщика 700/600. Снимки не отправляются в облако, публичного экспорта нет.
- История показывает до 50 последних JSON-файлов в local/diagnostics выбранного проекта. JSON читается только при открытии выбранного снимка, с лимитом 16 МиБ; symlink, другие папки и слишком большие файлы отвергаются. Повреждённый или неподходящий JSON не считается успешной диагностикой. Для чтения истории подключение ТВ не требуется.
- Снимок A хранится в памяти приложения; открытый другой снимок становится текущим B. Сравниваются только общие доступные RAM/audio/underrun и значения из фиксированного списка sound settings. Пропуски не заменяются нулями. Разница не считается приростом скорости или исправлением; одинаковое устройство/условия между старыми снимками не удостоверены, counters могут сбрасываться.
- Сохранённые sound settings показаны отдельной раскрывающейся секцией на Mac. Допускаются только известные ключи с целыми значениями; произвольные строки/аккаунты не показываются. Числа не обозначаются как проценты/dB: vendor-шкала и применение в DSP неизвестны.
- Новые снимки содержат expected_commands и collection_complete. Незавершённый или несовпадающий по числу команд сбор показывается как неполный. Старые снимки поддерживаются с пометкой о незафиксированной полноте; существующие raw-файлы не переписывались.

Нет служб автозапуска, постоянного опроса, установки APK, настройки ТВ, управления пультом или фоновой очистки. Cmd+Q во время операции отклоняется до её завершения: это предотвращает выход с работающим сборщиком; явной кнопки отмены пока нет. Закрытие окна не останавливает ограниченный сбор. Таймаут внешней команды — 10 секунд для обнаружения и 420 секунд для снимка; собственные команды сборщика ограничены отдельно.

## Сборка и проверки

Нужны **уже установленные** Xcode/Swift и codesign. Используются только системные Foundation/SwiftUI/AppKit; зависимостей/Swift packages нет. Текущая сборка — arm64, macOS 13+, для Mac пользователя; не магазинный и не notarized release. Подпись ad hoc локальная.

```sh
apps/metz-manager/check.sh
apps/metz-manager/build.sh
```

Единственная `.app`: `apps/metz-manager/build/METZ Manager.app`; в Git не входит. Сборка не запускает приложение и не обращается к телевизору. CLI core-check проверяет парсер/авторизацию устройств, частичные/старые снимки, несколько audio threads, whitelist звука, сравнение без выдуманных нулей, чтение истории и отказ для symlink/внешних/слишком больших файлов, timeout, ограничение stdout/stderr и literal arguments. Это не UI/E2E-тест.

В 0.2.0 core checks и 17 Python safety tests прошли, сборка и codesign verify прошли. Отдельный CLI integration check индексировал 18 имеющихся приватных файлов, распознал 16 снимков и прочитал sound settings в одном; raw/имена/идентификаторы не выводились. Два неподходящих JSON не интерпретировались как снимки. Это проверка общей логики чтения на Mac, а не работа кнопок интерфейса.

При ручном запуске пользователем: выбрать папку проекта → «Обновить устройства» → выбрать свой ТВ в состоянии `device` → профиль → «Снять диагностику». Профили исполняют **локальный Python-скрипт выбранного checkout**, поэтому выбирать нужно свой доверенный репозиторий. ADB/Python ищутся среди существующих стандартных мест установки; инструменты не устанавливаются.

Для ручного сравнения: «Обновить» в истории → выбрать снимок → «Открыть» → «Взять этот снимок как A» → открыть другой снимок. У обоих показан статус полноты; сравнение остаётся локальным и ничего не меняет на ТВ. Для проверки звука до/после сна нужно снять профиль «Звук» в обоих состояниях; само приложение не переключает sound profile и не включает/выключает ТВ.

UI на Mac и реальный сбор через кнопки ещё не проверены. Ранее ADB-диагностика звука выполнена отдельным сборщиком агентом, её нельзя записывать как испытание Manager. Для приёмки нужны ручные выбор папки/устройства, отказ при unauthorized/offline, снимок и сводка с ограничениями, история A/B, повторный запрос и завершение. Скорость и задержки остаются в финальном ручном чек-листе.
