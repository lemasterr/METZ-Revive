# METZ Home

Нативный launcher для METZ 32MTC6000Z: Kotlin и Android Views, однотонный тёмный фон, сетка приложений и видимый фокус клавиатуры. Предварительная версия 0.1.0 собрана и установлена как обычное приложение. UI и расход памяти на ТВ пока не проверены.

## Поведение

- Один ярлык на пакет; TV entry point предпочтительнее обычного mobile launcher. Kick и другие приложения без TV-ярлыка остаются доступны.
- Обновление каталога при открытии, по кнопке «Обновить» и событиям установки/удаления, пока HOME виден. Постоянного опроса нет.
- Небольшие иконки загружаются последовательно вне UI-потока. Bitmap-кеш ограничен 2 МиБ; при уходе с HOME кеш и видимые изображения освобождаются, worker останавливается. Это предел кеша, а не измеренный расход RAM всего процесса.
- Настройки: 3/4/5 приложений в ряду, системные настройки, отдельное включение возможности выбрать METZ Home.
- Кнопка «Штатный HOME» открывает сохранённый `com.google.android.tvlauncher`, без изменения default HOME.
- Нет Internet permission, сетевого кода, WebView, фоновых services, boot receivers, рекламы, виджетов или постоянных анимаций.

При установке `.HomeEntry` **выключен**: приложение доступно как обычный TV-ярлык и ещё не участвует в выборе HOME. Только действие «Настройки → Использовать METZ Home → Продолжить» включает его собственный HOME alias и открывает выбор в Android. Выбор default остаётся за пользователем; штатный launcher не отключается и не удаляется. До ручной проверки этот шаг не выполнять.

## Сборка

Использованы уже установленные Gradle 8.14.4, JDK 17, Android SDK 36 / Build Tools 35.0.0. Версии AGP 8.12.0, Kotlin 2.1.20 и annotations 23.0.0 закреплены. minSdk=26, targetSdk=35: приложение может работать на Android 11. Нативных ABI-библиотек нет. Это локальный debug APK, не релиз для магазина.

Указать `sdk.dir` в игнорируемом `local.properties` либо настроить `ANDROID_HOME`. JDK выбрать через `JAVA_HOME` или `-Dorg.gradle.java.home`. Зависимости сборки пользователь разрешил скачивать из проверенных источников; SDK auto-download отключён.

```sh
gradle --offline --no-daemon -p metz-home assembleDebug checkCatalog lintDebug
python3 -m unittest discover -s tests -v
```

`checkCatalog` выполняет чистые JVM-проверки: предпочтение TV entry point, устранение дублей и собственного пакета, стабильный порядок при одинаковых названиях, пустой каталог и mobile-only приложения. Он не запускает UI или эмулятор.

Только `google()` и `mavenCentral()` используются для артефактов. [verification-metadata.xml](gradle/verification-metadata.xml) хранит SHA-256 зависимостей и метаданных; последующие сборки должны проверять этот baseline, без автоматического переписывания. Первичная генерация сама по себе не удостоверяет происхождение кеша. Для четырёх ключевых компонентов отдельно сверены опубликованные Google/Maven Central контрольные суммы (SHA-256 для AGP/AAPT2, SHA-1 для Kotlin compiler/plugin); записи сохранены приватно. Метод — [Gradle dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html), формат TV-ярлыка — [Android TV](https://developer.android.com/training/tv/get-started/create), видимость приложений — [Android queries](https://developer.android.com/training/package-visibility/declaring).

При несовпадении hash остановиться и проверить официальный источник. Это контроль целостности, не антивирусный аудит всех зависимостей. Версии Gradle/AGP закреплены ради проверенной совместимости; lint может сообщать о более новом plugin. UI, speed и RAM gain успешной компиляцией не подтверждаются.

## Установка и ручная проверка

Установка обычного приложения выполнена по стоящему согласию на обоснованные обратимые изменения. До неё сохранены fingerprint, штатный resolver и отсутствие нового пакета. После установки проверены версия 0.1.0, TV-ярлык, отсутствие активного HOME alias, сохранение штатного HOME и защищённых приложений. Агент не запускал UI. Пакет: `com.metzrevive.home`; «Использовать METZ Home» пока не включать.

Ручной список: открыть METZ Home из штатного HOME; пройти сетку стрелками и Enter на имеющейся USB-клавиатуре; проверить TV Bro/Kick и возврат назад; проверить «Штатный HOME», настройки сетки и длинные названия. Отдельно оценить отображение на 1280×720 и масштабирование текста. Не требуется сравнение пультов: пользователь его исключил, физического пульта у него нет по исходному брифу.

После успешной ручной проверки — отдельное решение о выборе нового HOME и сопоставимых замерах RAM/CPU/отрисовки. Штатный launcher сохраняется.

## Возврат

Если METZ Home ещё проверяется обычным приложением, достаточно вернуться на штатный HOME. Если его alias включён и он выбран default, сначала в системных настройках выбрать штатный HOME. При недоступном интерфейсе и рабочем ADB вернуть сохранённый компонент штатного HOME, затем отключить только alias нового приложения:

```sh
# Для этой сборки ТВ исходный resolver подтверждён ранее; сверить перед применением
adb -s '<текущее устройство>' shell cmd package set-home-activity --user 0 com.google.android.tvlauncher/.MainActivity
adb -s '<текущее устройство>' shell pm disable --user 0 com.metzrevive.home/.HomeEntry
adb -s '<текущее устройство>' shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

Команды изменения default HOME описаны как будущий возврат, не исполнены: новый HOME ещё не назначался. Практически проверен возврат обычной установки до первого запуска: новый пакет удалён, отсутствие metadata и прежний штатный HOME прочитаны обратно; затем тот же подписанный APK повторно установлен. Финально версия 0.1.0, stopped=true/notLaunched=true, HOME alias выключен. Откат после пользовательских настроек и назначения HOME не проверен; удаление пакета удалит его будущие настройки. Команды не обеспечивают аварийное восстановление при потере ADB/загрузки.
