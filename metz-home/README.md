# METZ Home

Нативный launcher для METZ 32MTC6000Z: Kotlin и Android Views, без рекламы, сети и фоновых служб. **0.3.0 установлена поверх 0.2.0 по отдельному прямому согласию**; штатный HOME и данные сохранены.

## 0.3.0 — пользовательская дизайн-система

Основной источник — [metz-home-design](../docs/design/metz-home-design/SKILL.md), переданный пользователем 9 октября 2026. [Android-адаптация и ограничения](../docs/design/METZ_HOME_DESIGN.md).

- Общая навигация Главная / Приложения / Cast / Настройки и время TextClock. Главная содержит только Favorites; Recent/CPU/RAM/диагностики нет. Дефолты YouTube/Twitch/Browser сохраняются; пользовательское избранное не пересоздаётся.
- Палитра тёмно-синего фона и синего фокуса, крупные плитки с реальными banners/icons, подписи снизу, рамка 3 dp, радиусы 20/22 dp, промежутки 20 dp. Без blur/теней/анимаций. Сетка 3/4/5 столбцов сохранена; safe area 48 dp соответствует примерно 64 px на текущем ТВ.
- Cast показывает наличие включённого штатного receiver и краткий путь запуска с отправителя; он не начинает трансляцию и не имитирует состояние реального сеанса. Settings использует прокручиваемые действия и штатные диалоги в общей палитре.
- Одна активная страница, ограниченный icon cache 2 МиБ; логотипы загружаются только из установленных пакетов. Permissions и фоновые службы не добавлены. Wi-Fi-статус без достоверного источника не рисуется.

Strict offline assembleDebug/checkCatalog/lintDebug прошли: **0 ошибок / 4 прежних предупреждения**. 16 локальных safety tests и Manager core checks отдельно прошли. APK **141 312 байт**, SHA-256 `cdb48f4c419c0c58174b0d5d4b74142d6dd3ded5c3e5c5e5666bc857a4b70fec`; подпись проверена и совпала с сохранённым 0.2.0. Исходные версия/default HOME/alias/data inode прочитаны и сохранены приватно.

После согласия пользователя выполнен `install -r --user 0` точного APK 0.3.0. Версия 0.3.0 подтверждена; default HOME, список HOME candidates и inode данных совпали с исходными. Данные не очищались; содержимое preferences без root не сравнивалось. UI агент не запускал. Возврат предусмотрен на точный подписанный 0.2.0 с `install -r -d --user 0`; его прежний возврат на 0.1.0 уже проверялся, но возврат **из 0.3.0** ещё не испытан. Визуальные проверки пользователь выполняет сам; [финальный чек-лист](../docs/FINAL_MANUAL_CHECKS.md). Скорость/latency не отмечены пройденными.

## Две страницы

- **Главная**: выбранные приложения. При первом создании избранного — доступные YouTube, Twitch и браузер; предпочтение No BS, затем Mrowser, затем TV Bro. Сохранённый пустой список не заполняется заново.
- **Приложения**: доступные потребительские приложения, поиск по названию и звёздочка на каждой плитке. Звёздочка добавляет приложение на главную или убирает оттуда, без удаления самого приложения. Порядок избранного сохраняется.
- Вкладки подписаны; обновление, настройки и возврат к штатному HOME — кнопки-иконки с доступными названиями. Подсказок «стрелки/Enter» на экране нет.
- Сетка 3/4/5 столбцов, по умолчанию 5, промежутки 8 dp. Короткий ряд избранного не растягивается на весь экран. У плиток и звёздочек есть явные направления клавиатурного фокуса; фактическая навигация на ТВ ещё ожидает ручной проверки.
- Один ярлык на пакет, TV entry point предпочтительнее mobile. Kick остаётся доступен.

Каталог исключает отключённые/приостановленные приложения, недоступные извне Activity, собственный пакет, HOME, настройки и помощник atvTools. Системный или обновлённый системный пакет скрывается, если он не входит в небольшой список известных потребительских приложений. Это сохраняет предустановленный YouTube: исключать все FLAG_SYSTEM означало бы скрыть и его. Магазин/известные медиаприложения могут отображаться; vendor factory/demo/службы скрыты. Неизвестное предустановленное приложение может потребовать добавления в список после проверки его назначения. Фильтрация ничего не отключает на телевизоре.

## Нагрузка

Один GridLayout в ScrollView, один текущий набор плиток. Переключение страницы перестраивает только эту область; скрытой второй сетки нет. Поиск работает по небольшому каталогу в памяти, без повторного обращения к PackageManager; ввод объединяется с задержкой 100 мс только на странице приложений.

Каталог обновляется при открытии, по кнопке и событиям установки/удаления/изменения пакета, пока приложение видно. Постоянного опроса нет. Иконки загружаются последовательно вне UI-потока и только для видимой области; при смене страницы задачи отменяются, устаревшие результаты отбрасываются. Кеш ограничен 2 МиБ. При уходе с HOME worker останавливается, кеш и ссылки на изображения освобождаются. Это предел кеша, а не измеренный расход RAM всего процесса. Для небольшого каталога этого ТВ выбран обычный native layout; виртуализация сотен приложений не реализована.

Нет permissions, services, boot receivers, WebView, фоновых сетевых запросов, виджетов или постоянных анимаций. Успешная сборка не доказывает выигрыш скорости или RAM.

## Обновление и возврат

На ТВ проверена последовательность: установка 0.2.0 с -r → возврат подписанного debug APK 0.1.0 с -r -d → повторная установка 0.2.0. После каждого шага прочитаны версия, default HOME, список HOME alias и inode каталога данных; HOME/alias/inode не изменились. Данные не очищались. Содержимое пользовательских preferences без root не сравнивалось; UI после возврата не проверялся.

```sh
# Подставить текущий serial и сохранённый локальный APK той же подписи
adb -s '<текущее устройство>' install -r -d --user 0 '<APK METZ Home 0.1.0>'
```

Если новый launcher когда-либо выбран default, сначала выбрать штатный HOME в Android. При рабочем ADB можно восстановить ранее подтверждённый компонент и отключить только новый alias:

```sh
adb -s '<текущее устройство>' shell cmd package set-home-activity --user 0 com.google.android.tvlauncher/.MainActivity
# На текущей nondebuggable сборке этот alias восстанавливается манифестом rollback APK.
adb -s '<текущее устройство>' shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

Смена default агентом не выполнялась. Практический возврат свежей установки 0.1.0 до первого запуска также ранее проверен удалением/повторной установкой. Удаление после настройки уничтожит preferences, поэтому для возврата версии теперь используется обновление APK. Это не аварийное восстановление при потере ADB или загрузки.
