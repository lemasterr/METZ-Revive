## Что подтверждено и что ещё открыто

Все четыре нативные сборки, Manager core/fake ADB, Display framing/NAL/pin checks, Home catalog и TV protocol checks прошли. Android сборки используют strict offline verification, R8/resource shrink и прежнюю подпись. Home APK после исправления удержания OK60 920 Б, TV Display57 288 Б. Lint: Home0 ошибок/17 предупреждений, Display0/7; предупреждения не скрывались. Новых зависимостей и постоянных фоновых опросов нет.

Read-only снимок ТВ показал отсутствие слушателя Display на порту47421, совпадение времени с Mac и отсутствие ошибок в коротком доступном журнале. Это описывает момент снимка, а не доказывает причину предыдущей ошибки пользователя. Добавленные проверки устраняют попытку подключения к неподтверждённому приёмнику и делают причину отказа понятнее; успешная передача экрана ещё не доказана.

На пользовательском снимке Manager показал доставку команды28мс. Это сообщение работающего приложения об ответе канала, а не измерение времени до отрисовки ТВ. Ранее канал запускал отдельный Android input process на кнопку; быстрый канал сохраняет один shell и ограниченную очередь. Сетка десяти приложений сохраняет кеш2МиБ и загрузку только видимых иконок. Числовой выигрыш RAM/CPU/FPS и устойчивость после standby не измерены.

После отключения stock его процесс остался в состоянии cached=true/empty=true: meminfo показывал PSS25 319КиБ. Завершён только этот фоновый процесс через адресный am kill для user0. Повторное чтение pidof не обнаружило процесса; HOME/stock enabled-state/data/ADB сохранены. Это подтверждает отсутствие старого launcher в данном снимке, но не измеряет чистый прирост свободной RAM и не обещает рост FPS. Принудительный force-stop и очистка данных не применялись.

Заставка уже отключена, idle30мин и sleep3часа сохранены и перечитаны. Отказ от заставки не запрещает Android освобождать кешированные процессы. Cast/сеть/ADB/ввод/резервные браузеры сохраняются.

## Особенности прошивки при применении

Android отказал shell в изменении состояния отдельного HomeEntry у nondebuggable приложения. Вместо этого HomeEntry включён в подписанном манифесте; оптимизация и защита сохранены. Команда set-home-activity сообщала Success, пока включённый stock с priority2 оставался результатом resolver. После проверенной доступности нового candidate и согласованного disable-user stock повторный выбор дал METZ HomeEntry. При промежуточных отказах скрипт возвращал штатный HOME и старый код равными versionCode; данные сохранились. Итоговая пачка применена полностью, промежуточные ошибки не выдаются за успешную установку.

## Возврат

Перед возвратом APK сначала вернуть stock HOME: `adb -s <TV> shell pm default-state --user 0 com.google.android.tvlauncher`, затем `cmd package set-home-activity --user 0 com.google.android.tvlauncher/.MainActivity` с тем же `adb -s <TV> shell`. Проверить HOME resolver. Затем установить подготовленные rollback APK командой `adb -s <TV> install -r <APK>` без удаления данных: старый манифест сам возвращает HomeEntry в disabled default. Shell-команды enable/disable/default-state для этого отдельного компонента на данной прошивке запрещены. Старый код имеет равные versionCode; исходные более низкие APK могут не допускать downgrade.

Точные приватные пути/состояния и подписанные артефакты находятся в игнорируемом local/usability-20261010. Mac возврат: заменить новые Applications bundle сохранёнными приватными копиями/архивами. Промежуточный TV возврат реально применялся и проверен чтением; полный возврат после итогового отключения stock и замены Mac не запускался. Штатный launcher остаётся установленным; его APK и данные не удаляются. На ТВ версии наших приложений обновляются под прежними package ID, отдельные старые копии не создаются.

Дополнительно сохранены APK и исходники установленного Home0.6 до исправления удержания OK: codex/rollback-home06-before-favorite-fix. Исправление обновляет ту же локальную0.6/code6; полный возврат к0.5 по-прежнему использует прежнюю последовательность со stock HOME.

## Приёмка и план

1. Manager: компактный пульт при минимальном окне; оба канала без переносов; стрелки/Return/Escape вне поля, обычное редактирование внутри поля; Home/Back/звук.
2. Home: два ряда, переход вправо/влево из обоих рядов, неполная последняя страница, поиск, настройки. Удержать OK на приложении → отпустить: меню должно остаться открытым без выбора; перейти стрелками к нужному пункту → нажать OK отдельно. Проверить добавление/удаление/перестановку и «О приложении».
3. Display: подготовить ключи → нажать «Подтвердить и принимать» на ТВ → подтвердить доверие → подключить в Manager. До принятия должна появляться понятная подсказка. Затем перенести окно, проверить изображение/курсор, остановку и отсутствие оставшегося виртуального экрана.
4. После применения default HOME: вручную нажать Home, проверить обычный запуск, естественный standby/пробуждение и ADB. Не проводить перезагрузки/стресс-тест для галочки.

По дорожной карте реализация Home/Manager дополнена; этапы7/9/12/13 не считаются полностью принятыми до этих ручных проверок. Cast и улучшение звука ранее подтверждены пользователем; новая задержка, Display runtime и повтор после сна открыты. Дополнительные идеи после приёмки: перестановка избранного непосредственно стрелками; кнопка повторного сопряжения; короткая история фактических измерений отклика. Расписания обслуживания, прошивка и аварийное recovery остаются отдельными незавершёнными направлениями.
