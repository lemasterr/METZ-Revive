# Восстановление — предварительный план

Дата: 9 октября 2026. **Готовность аварийного восстановления не подтверждена.** Не запускались recovery, factory reset, reboot, root, bootloader unlock или запись разделов.

## Что известно

- ADB shell доступен сейчас; USB-клавиатура работает по сообщению пользователя, физического пульта нет.
- Есть block aliases `boot`, `recovery`, `misc`, `upgrade`, `system`, `vendor`, `vbmeta`, MBOOT/MBOOTB и vendor-разделы. Наличие двух MBOOT не доказывает полноценный A/B Android.
- `/vendor/etc/recovery.img` существует, размер 33 554 432 байта. Читать/копировать этот образ не пытались; наличие файла не доказывает его пригодность для восстановления экземпляра.
- `/cache/recovery` закрыт для shell; recovery-persist также закрыт. Реальный способ входа и клавиатурная навигация recovery неизвестны.
- `verifiedbootstate=green`, SELinux Enforcing. Lock state и OTA topology не установлены.
- `com.airoha.ble.ota` относится к BLE-компоненту; наличие этого пакета **не подтверждает обновление прошивки самого телевизора**.

## До любого изменения

1. Убедиться, что USB-клавиатурой можно управлять обычным HOME и настройками. Это резерв для потери виртуального пульта, а не гарантия управления recovery.
2. В приватный локальный журнал сохранить пакет, user ID, исходный enabled-state/значение конкретной настройки, причину, точную операцию и точный обратный шаг.
3. Сохранять штатный HOME `com.google.android.tvlauncher`, ADB, USB debugging, сеть и ввод. Не отключать Cast, atvTools/helper, аудио, TV input, power, framework и vendor TV services.
4. Один обратимый кандидат за раз; заранее определить ручной путь возврата при потере ADB. Если его нет — не применять.
5. Согласовать действие непосредственно перед изменением; после сравнить функциональность и ресурсы в том же сценарии. Отрицательный или неясный эффект — основание вернуть исходное состояние.

## Обратимые операции: план, а не выполненные команды

| Будущее действие | Сохранить до изменения | Возврат и ограничения |
|---|---|---|
| `pm disable-user --user 0 <package>` | Установленность, исходное `enabled` и зависимости; отдельное согласие на конкретный пакет | `pm default-state` при исходном 0 или `pm enable` при исходном 1. Другие исходные states требуют соответствующего возврата; слепой enable не восстанавливает default точно |
| Изменение одного setting | Namespace/key, конкретное старое значение или отсутствие key | Вернуть старое значение; при исходном отсутствии — удалить только созданный key. Не выполнять очистку namespace |
| Изменение каналов/качества в UI | Исходные выбранные каналы/качество | Ручной возврат с USB-клавиатуры; UI-проверка требует разрешения |
| Будущий новый launcher | Штатный HOME и рабочая USB-навигация | Вернуть штатный HOME через settings; ADB-путь предварительно проверять для этой прошивки. Оригинальный launcher не отключать до проверки замены |

Эти команды не выполнены. Универсальный rollback-script пока не создан: нет согласованной операции и исходного состояния для него. Удаление приложения, `clear data` и очистка кеша не имеют равнозначного отката через `enable`; не использовать их как первый эксперимент.

## Если ADB потерян

Не запускать автоматически reset или firmware recovery. Сначала ограниченно проверить сеть и адрес, затем USB-клавиатурой восстановить обычную настройку/пакет, если такой путь доступен. Без сети/ввода/загрузки обычный ADB rollback не поможет. Требуется подтверждённая процедура производителя; гарантии сейчас нет.

## Factory reset, USB и официальная прошивка

Штатный reset нужно подтвердить для конкретной прошивки, он удаляет пользовательские приложения/аккаунты/настройки и требует отдельного согласия. Он не является доказанным лечением отсутствующего класса в read-only system APK и не равен восстановлению firmware image.

В просмотренных официальных материалах [METZ для серии MTC](https://metzblue.com/support/downloads/declaration-of-conformity/mtc) и [листе 32MTC6000Z](https://metzblue.com/fileadmin/Datasheet/MTC6000/32MTC6000Z_Data__Sheet_EN.pdf) нет найденного совместимого USB recovery image. Поиск не исчерпывает каналы поддержки. Ссылка на декларацию/спецификацию не является ссылкой на прошивку.

Следующий шаг — пользовательский запрос официальной поддержке METZ о модели, региональной версии, board/revision, текущем build и точной USB/recovery процедуре. Самостоятельно сообщения не отправлять. Серийный номер или фото маркировки передавать только через согласованный приватный канал; в публичный GitHub их не включать.

Перед будущей прошивкой нужны подтверждение аппаратной совместимости, официальный источник и проверка checksum/signature, процедура восстановления с имеющейся клавиатурой, перечень потеряемых данных и отдельное решение пользователя. Не скачивать случайные образы по одному совпадению `m5621`.

## Что не является backup

- `getprop`, package list, dumpsys и экспорт selected settings — диагностические данные, не полный образ устройства.
- Rootless ADB не даёт здесь подтверждённой возможности сохранить приватные данные всех приложений, calibration/NVRAM, DRM keys и boot partitions.
- Наличие `ALLOW_BACKUP` у пакета не гарантирует usable backup на этой Android TV сборке. `adb backup` не проверялся и не предлагается как универсальное восстановление.
- Factory/NVRAM/DRM/сертификаты не читать и не публиковать. Клонирование их с другого телевизора недопустимо как предполагаемый способ ремонта.

## Критерии готовности следующего этапа

Точный кандидат и причина известны; зависимости рассмотрены; исходное состояние сохранено локально; возврат описан без потери ADB/ввода; пользователь согласовал действие; есть сопоставимый сценарий проверки. Для записи firmware или системных разделов дополнительно требуется подтверждённое восстановление производителя. Сейчас последний критерий не выполнен.
