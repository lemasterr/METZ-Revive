# Подключение по кнопке и темп декодера: Manager 0.7 / TV Display 0.5

10 октября 2026. Прямой запрос пользователя: подтверждать доверие на ТВ один раз, затем подключаться с ноутбука без ручного открытия Display; не создавать постоянную фоновую нагрузку. Пользователь также сообщил точную ошибку «ТВ не успевает декодировать кадры» после предыдущей пачки. Это подтверждает срабатывание защиты очереди по сообщению пользователя; фактическая скорость аппаратного декодера не измерена.

## Подключение и доверие

Manager по кнопке «Подключить второй экран» отправляет запрос в `SessionRequestReceiver`, защищённый `android.permission.DUMP`, затем явно открывает Activity через авторизованный ADB. Запрос сверяется с сохранённым отпечатком Mac и разрешает только один запуск в течение10секунд. Внешний intent сам по себе не разрешает автоматический приём. Сеть сохраняет взаимную TLS-аутентификацию и проверку закреплённых сертификатов.

Если ключ ещё не подтверждён или изменился, Manager открывает форму ТВ и просит один раз подтвердить доверие. Сохранённое доверие предыдущей версии используется из того же приватного `ReceiverActivity` preferences; обновление не очищает данные. Для прежнего подтверждённого ключа повторного диалога нет. Новый ключ требует нового согласия. Сохранённые папка ключа и отпечаток ТВ на Mac остаются прежними.

Receiver запускается только при пользовательском запросе. В manifest нет service, boot receiver, alarm или фонового поиска Mac. Listener ожидает соединение максимум20секунд; после окончания сеанса Activity завершается, socket/server закрываются, очередь очищается и decoder освобождается. Уход Activity в фон и Back также останавливают ресурсы. Android может сохранить обычный кешированный процесс в RAM; это не постоянный сетевой listener или активный worker. Фактические CPU/RAM после новой ручной сессии пока не измерены.

TV должен быть включён и доступен по уже разрешённому ADB. Автоматическое пробуждение выключенного ТВ не добавлено. Подключение выводит fullscreen приёмник на ТВ; другие приложения в этот момент уходят в фон. Проверка готовности выполняется только по нажатию, без постоянного polling.

## Ошибка перегрузки

Прежнее завершение `NWConnection.send` означало принятие данных сетевым стеком Mac, а не готовность декодера ТВ. Даже ожидание свободного места в очереди500мс оставляло возможность её переполнения. Теперь отправитель ждёт отдельное подтверждение ТВ **после успешного `MediaCodec.queueInputBuffer`** и освобождения доступных выходных buffers. [Документация Android MediaCodec](https://developer.android.com/reference/android/media/MediaCodec) описывает отдельную выдачу входных/выходных buffers и возможность остановки работы при удержании buffers.

- Один сжатый кадр ожидает подтверждения; до этого на Mac хранится только последний исходный кадр. Промежуточные raw-кадры заменяются до кодирования, зависимые H.264 P-кадры не выбрасываются.
- Подтверждение содержит PTS данного кадра. Sender проверяет PTS и учитывает оба порядка callbacks: ACK до/после network completion. Ошибочный или повторный ACK не освобождает текущий кадр.
- Подтверждается **приём декодером**, а не фактическое появление каждого кадра на панели. Подтверждение первого декодированного кадра остаётся отдельным сообщением.
- Receiver заранее сообщает поддержку этого протокола; несовместимая старая пара завершается с ограниченным ожиданием, без тихой отправки без контроля темпа.
- Остаются1280×720, максимум30 кадров/сек и аппаратный H.264. Фактический темп зависит от декодера и сети. Deadline3сек для передачи/приёма кадра сохраняет остановку при зависании; защитный предел очереди остаётся. Новая скорость и устранение пользовательского обрыва ещё не подтверждены runtime-проверкой.

## Проверки, установка и возврат

Итоговая пара **Manager0.7.0 / TV Display0.5.0/code10 установлена** по прежнему разрешению автоматически ставить готовые обновления. Подтверждены версии, прежняя подпись APK и designated requirement Manager, сохранение data inode/HOME/IME/ADB. Новый protected receiver найден в APK manifest и адресным `query-receivers`; эти проверки компонент не запускали. Отдельный Mac Display не возвращался.

- Manager core и fake ADB: запрос доверенной/новой сессии, недопустимый ключ, parsing/readiness и прежние checks — passed. Это заглушка ADB, не настоящий запуск Activity.
- Display core: network/decoder ACK в обоих порядках, несовпадающий PTS, повторный ACK, размер/big-endian receipt, framing/pins и encoder frame-drop policy — passed. Adapter проверен doubles, без настоящего экрана.
- TV JVM: одноразовый запрос отклоняет неизвестный/изменённый ключ, истечение10секунд, повтор и неверное время; очередь/протокол и формат admission receipt — passed.
- Native build/signature и strict offline localOptimized Android build/lint — passed:0ошибок/7предупреждений. Manifest проверен на отсутствие service/boot/scheduled receivers; запрос защищён DUMP. Инструменты/зависимости не устанавливались.

UI/capture/реальный запуск приёмника, жизненный цикл на ТВ, аппаратный decoder ACK и перенос окна агентом в этом запросе **не проверялись**; пользователь проверяет вручную. Успешные локальные проверки не удостоверяют реальную стабильность нового видеотракта или нулевой расход RAM.

Прежние Manager0.6.4/TV receiver0.4.1, исходники и установленный APK сохранены в игнорируемом приватном `local/display-demand-connect.noindex/`. Для возврата TV собран прежний код0.4.1 с прежним сертификатом и повышенным code11 (`0.4.1-rollback`), для итогового обновления — code10. Это позволяет адресную установку `-r` без downgrade/удаления данных. После возврата code11 последующая новая версия должна иметь code выше11. Обе стороны протокола возвращать согласованно: прежний Manager не понимает новый ACK handshake. Полный возврат Mac/TV пачки не запускался.

При первой установке проверка ошибочно требовала наличия receiver без intent-filter в выводе `dumpsys package`. Автоматический откат TV к прежнему коду с промежуточным code9 выполнен и подтверждён; data inode/HOME/IME/ADB сохранены, Manager тогда ещё не заменялся. Это ошибка агентской проверки, не доказанный отказ компонента. Итоговая проверка использует адресный `query-receivers`, не запускающий компонент. После отката versionCode повышен до10; исправление приложения не менялось ради этой проверки.

## Ручная приёмка и дорожная карта

1. Полностью закрыть Manager через Cmd+Q и открыть установленную версию. На включённом ТВ можно оставить Home или другое приложение.
2. В разделе «Экран» нажать «Подключить второй экран». При прежнем сохранённом доверии приёмник должен открыться автоматически. Только для нового ключа подтвердить его на ТВ и снова нажать подключение.
3. Переместить курсор и одно окно, проверить счётчик «Принято декодером». Он не является замером кадров на панели.
4. Нажать «Остановить»: приёмник должен закрыться. Повторить подключение с ноутбука без открытия Display на ТВ. При ошибке записать точный текст/время.

Этап13 остаётся активным до этого результата; скорость, длительная стабильность, остановка/повторное подключение и звук после standby остаются ручной финальной приёмкой. Новый этап не добавлен.
