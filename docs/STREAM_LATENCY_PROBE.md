## Изменения и основания

1. ACK и телеметрия раньше записывались в TLS непосредственно на MediaCodec callback handler. Любой blocking socket write мог задержать выдачу output callbacks. Теперь один session-owned `ReceiptWriter` сохраняет порядок, без ожидания на decoder thread; максимум32 пакета по8192байт. Переполнение или IO failure завершают сеанс, ACK не теряется молча. Stop закрывает socket, очищает очередь и прерывает worker; network finalization ограниченно ждёт его завершения. Это исправление блокирующего участка кода; его вклад в реальные176мс ещё не измерен.
2. Стандартный `KEY_LOW_LATENCY=1` запрашивается при configure, даже если vendor feature bit не объявлен. При configure/start exception создаётся один новый decoder с прежним baseline format; failed instance освобождается. Поддержка не утверждается по факту принятия ключа. [Android MediaFormat](https://developer.android.com/reference/android/media/MediaFormat#KEY_LOW_LATENCY) описывает уменьшение удержания данных в таком режиме. В [Moonlight helper](https://github.com/moonlight-stream/moonlight-android/blob/master/app/src/main/java/com/limelight/binding/video/MediaCodecHelper.java) стандартный запрос также пробуется без feature bit с configuration fallback. Vendor-specific keys не применяются.
3. Output release использует текущий monotonic timestamp вместо boolean render. Это позволяет Surface отбросить старый ещё не показанный кадр при догоняющем output burst, сохраняя декодирование всех compressed references. Не добавляет будущего presentation wait. [Android MediaCodec](https://developer.android.com/reference/android/media/MediaCodec#releaseOutputBuffer(int,%20long)). Настройка не исправляет уже накопленную задержку внутри самого decoder.
4. Mac capture задаёт явный minimumFrameInterval1/60 для собственного60Hz дисплея (выбор30/50 остаётся отдельным clock), вместо zero minimum. [Apple minimumFrameInterval](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/minimumframeinterval). Capture переведён на поддерживаемый [420v/NV12](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/pixelformat), который уже проходит hardware encode fixtures. Это снижает размер удерживаемых raw surfaces и переносит RGB→YUV преобразование на capture backend; реальное ускорение и fidelity требуют сравнения.
5. Numeric capture event получает delivery_ms от `SCStreamFrameInfo.displayTime` (mach absolute time) через явную конверсию host units. Отсутствующее metadata не заменяется нулём, epoch sample PTS не предполагается равным host time. UI/analyzer показывают доставку отдельно от encoder/ACK. [Apple displayTime](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/displaytime), локальные SDK headers подтверждают mach units. Это время WindowServer→callback, не end-to-end latency ТВ.
6. Для отдельно разрешаемого runtime fixture добавлена generated rotating gradient grid по большей части кадра. Режим bar сохранён. Grid не заменяет приёмку настоящего видео; CADisplayLink по-прежнему считает только callbacks, фактический source FPS определяется capture complete.

## Проверки и возврат

Mac/Manager builds, core/journal/doubles/fake/owned helper,48 hardware-generated frames/12 modes/ref1, clock/grid/repeat/fresh/stop/paced backpressure checks и4 Python analyzer regressions прошли. Grid здесь означает PTS grid: визуальный rotating-grid fixture пока не запускался. TV strict offline build, JVM receipt writer bounded/nonblocking/order/failure/stop и optional-config fallback tests прошли; lint0errors/7warnings. Новые/старые APK29/31/32 подписи совпадают. Installed29 APK точь-в-точь совпал с сохранённым readback. Manager22/installed21/exact backup21 strict signatures и сертификаты совпадают.

Raw journal и baseline snapshots приватны в `.noindex`. Exact Manager21 bundle/source сохранён; TV29 implementation rollback подготовлен сcode32, versionName0.7.4, прежней подписью (обычный downgrade не нужен). HOME/IME/data inode/hour timer исходное состояние сохранено чтением. Возврат новой пачки ещё не применялся. Установка завершена: installed Manager executable и APK31 точь-в-точь совпали с подготовленными; подписи совпадают, version/build/code прочитаны. HOME/IME/data inode/hour timer после установки совпали с исходным состоянием, stream receiver/decoder/audio/IDR/receipt workers отсутствуют. Manager штатно закрыт перед заменой. Новые UI/capture/device tests и изменения системных настроек не выполнялись.

Риски: optional decoder key может игнорироваться или давать runtime regression после configure; Surface drop меняет выбор показа при burst; NV12 может менять цвет/читабельность; bounded writer при недоступном peer завершает session. Драйверы, frequencies, thermal/security controls и системные настройки не меняются. Установка готовой пачки отдельно разрешена и выполнена. Ответ разрешал установку; новый rotating-grid capture-сценарий не запускался. Следующий шаг — тот же пользовательский видео/курсор30/60 с автоматическим числовым журналом; адресное grid runtime сравнение остаётся отдельно согласуемой проверкой. Сравнить source/fresh/repeat, capture delivery, decode delay/output gaps и cleanup. Не заявлять устранение проблемы до результатов.
