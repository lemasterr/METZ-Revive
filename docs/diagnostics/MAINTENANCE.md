# Этап 10 — обслуживание по запросу

По поручению продолжать независимые работы подготовлена безопасная основа обслуживания. Шесть последовательных ADB-команд читают RAM, файловую систему для `/data`, установленные/включённые/отключённые пакеты user 0 и версию METZ Home. Поиск устройства и сбор разделены; serial у каждой команды явный. Пределы прежнего сборщика: 20 секунд и 256 КиБ на поток каждой команды. Записей на ТВ нет.

Автоматические расписания, LaunchAgent, фоновый сервис, очистка, перезагрузка и изменение настроек не созданы. Сначала используется короткая проверка по запросу без постоянной нагрузки на слабый ТВ. Полный этап автоматического обслуживания остаётся частичным: политика расписания и действия восстановления не выбирались и не применялись. Нативный Manager остаётся 0.2.0; новый профиль и отчёт пока доступны из CLI, интерфейс приложения не изменялся.

## Использование

Нужны уже установленные ADB и Python 3.9+, дополнительных зависимостей нет. Перед каждым новым сбором проверить устройство в состоянии `device`; метка нового снимка должна отличаться от существующих.

```sh
adb devices -l
python3 scripts/collect_diagnostics.py --serial '<текущее устройство>' --profile maintenance --label maintenance-check
python3 scripts/maintenance_report.py local/diagnostics/maintenance-check.json
python3 scripts/maintenance_report.py local/diagnostics/maintenance-check.json --format json --output local/maintenance-report.json
```

Сборщик хранит исходные результаты в ignored `local/diagnostics` (700/600). Генератор работает на Mac без подключения к ТВ. Он принимает только обычный файл из этой приватной папки, ограничивает чтение 16 МиБ и отклоняет symlink. `--output` создаёт новый файл с правами 600; существующий отчёт не перезаписывается.

В отчёт входят только контролируемые числовые показатели, время ISO, числовая версия Home и состояния фиксированного набора пакетов. Raw, адрес устройства, имя снимка, полный список приложений, пути устройств и произвольные строки не экспортируются. Это не универсальный санитайзер для других raw-профилей: принимается только `maintenance`.

## Как читать результат

- «Сбор завершён» подтверждает число сохранённых команд и флаг завершения; это не заключение об исправности.
- Ошибка shell, stderr, timeout или обрезка исключают данные команды из фактов. Нераспознанный формат и противоречивые списки дают неизвестное состояние. Пустой список установленных пакетов не считается удалением всех приложений.
- MemAvailable — текущая оценка Android; один срез не доказывает ускорение или отсутствие проблем памяти. Порог «нужно чистить RAM» не задан.
- `/data/user/0` — фактическая точка монтирования, которую данный ТВ возвращает для `df -k /data`; отчёт использует размер в КиБ. Свободное место не считается оценкой ресурса накопителя.
- Включённый пакет для user 0 не подтверждает запуск приложения, default HOME, alias, точный код override или работу телефонного управления. Anoki включён после прежнего возврата; эта проверка не означает повторное применение оптимизации.
- При недоступном важном пакете или нуле доступного места предлагается ручная проверка журнала. Никаких автоматических исправлений нет. Звук после сна этим профилем не диагностируется и не исправляется.

Настройки и питание ТВ не менялись.

29 Python tests прошли: прежние ограничения сборщика/отката и новые проверки профиля, полноты, ошибок, формата mount, `android` без точки, противоречий пакетов, отсутствия приватных строк, границ файла и сохранения существующего отчёта.
