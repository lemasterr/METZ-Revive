# Управление Mac и исправление TLS — 10 октября 2026

Установлены METZ Manager 0.6.0, METZ Home 0.7.0, TV Display 0.4.0 и резервный Mac Display 0.4.0. Пользователь разрешил устанавливать готовые обновления сразу. Приложения Mac находятся в пользовательской Applications; агент их не запускал.

## Реализованные запросы

- **Ввод с Mac:** отдельный режим во вкладке «Пульт», вставка из буфера по кнопке, отправка текста, поиск, удаление символа, очистка текущего поля на ТВ и Enter. После подтверждения доставки буфер ввода очищается. Частично выполненный поиск сообщает, что текст доставлен, но редактор не поддерживает поиск: повтор не должен дублировать текст. Текст не сохраняется в истории и не логируется. Требуются активное поле и выбранная клавиатура Mac; ограничения стороннего редактора не обходятся.
- **Восстановление:** отдельная проверка соединения читает состояние питания. Сон, заставка, отсутствие ADB и неизвестное питание различаются; отсутствие ADB не выдаётся за доказательство сна. Экран различает незапущенный приёмник и подтверждение другого ключа Mac. Действия предлагаются пользователю, без автоматического пробуждения или обхода доверия.
- **Диагностика:** последние 30 событий CPU/доступной RAM и доставки команд, с временем, сохраняются локально отдельно для каждого ТВ. Опрос показаний выполняется по кнопке. Доставка — подтверждение команды, не задержка отображения результата. Пропущенные показатели остаются неизвестными.
- **Настройка Home с ноутбука:** «Приложения → Настройка Home на ТВ»: загрузить текущую конфигурацию, выбрать порядок трёх разделов, плитки 2×4 / 2×5 / 2×6, автоматические / видимые / скрытые названия и применить. По умолчанию сохраняется 2×5 и формат плиток 16:9. Настройки обновляют видимый Home без фонового опроса; данные избранного сохраняются. Endpoint защищён системным разрешением DUMP, значения проверяются по списку допустимых вариантов.

## Реальная причина отказа экрана

Разрешённая отдельная TLS-проверка воспроизвела отказ при `listening=true` и `trusted=true`: ключ Mac был правильным. Журнал Keystore сообщил `InvalidKeyException / Incompatible padding mode`; Mac получил TLS OSStatus -9816. Ограничение проверки TLS 1.2 не исправило проблему и в продукт не добавлялось.

Прежняя конфигурация RSA-ключа ТВ не разрешала необходимые Conscrypt операции. Исправлены параметры ключа: digest NONE для предварительно вычисленного TLS-хеша и соответствующие RSA padding/purpose. Основание: [Android KeyGenParameterSpec.Builder — setDigests / setEncryptionPaddings](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder). TLS 1.2+ и взаимная проверка полных SHA-256 отпечатков сохранены.

Пользователь отдельно подтвердил создание нового ключа **только TV Display**. Новый ключ находится под отдельным alias v2; v1 не удалён и не перезаписан. Key manager предоставляет только v2, чтобы система случайно не выбрала оставшийся v1. Ключи Mac и ADB не менялись. После установки пользователь вручную открыл приёмник и подтвердил приём; агент подключил только TLS, без кадров, захвата и создания виртуального экрана. Результат: **TLS_READY на настоящем ТВ**.

Также исправлен отдельный дефект: новый ключ Mac теперь останавливает слушатель со старым ключом и заполняет поле для нового локального подтверждения. Доверие не назначается автоматически. Ошибки handshake больше не выдаются все за неверный ключ.

После смены ключа ТВ в Manager необходимо заново нажать «Подготовить подключение»: сохранённый старый отпечаток ТВ больше не подходит. Успешная TLS-проба завершила свой сеанс; для передачи изображения потребуется снова включить приём на ТВ.

## Проверка, сохранение и откат

Home и receiver: strict offline assembleLocalOptimized, JVM behavior checks и lint прошли. Lint: Home 0 ошибок / 17 предупреждений; receiver 0 / 7. Manager: core checks и нативная сборка; Mac Display: core checks и нативная сборка. Подписи Android/Mac проверены. Новых инструментов и зависимостей не устанавливалось.

Проверены установленные версии, сохранение inode данных Home/Display, default METZ HOME, IME, ADB и состояния штатного launcher. Никаких новых изменений звука, сна или защищённых системных пакетов эта пачка не делает. В активных местах Mac оставлена одна установленная версия каждого приложения; предыдущие bundles лежат в приватном месте для восстановления и не имеют расширения `.app`.

Исходники предыдущей рабочей пачки сохранены в Git `codex/usability-refinement-snapshot`. Подписанные rollback APK Home 0.6 и receiver 0.3 собраны с кодами обновления 7/5, чтобы возврат не требовал стирания данных или запрещённого downgrade nondebuggable APK. Старые bundles, APK, отпечатки и журналы находятся только в игнорируемом `local/`. Возврат receiver использует сохранённый alias v1; затем требуется восстановить прежний отпечаток ТВ на Mac и подтвердить приём. Полный откат этой новой пачки на устройстве не запускался.

## Что ещё не подтверждено

Ручная приёмка нового ввода в сторонних приложениях, конфигурации Home, фокуса/избранного и визуальных отступов остаётся открытой. Захват, private API виртуального дисплея, изображение на ТВ, FPS, stop/reconnect и поведение после сна агент не запускал. Успех TLS не доказывает работу всего видеотракта.

По звуку пользователь ранее сообщил улучшение после одной согласованной перезагрузки. Причина исходного приглушённого звука не установлена; устойчивое исправление и отсутствие возврата после сна не подтверждены. Эта пачка не является исправлением звука.
