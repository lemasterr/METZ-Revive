## Доказательства и изменения

Пользователь сообщил: доступ к записи экрана уже выдан, но приложение снова его запрашивает. Проверка установленных bundles подтвердила ad-hoc подпись и designated requirement с CDHash. Такая идентификация меняется при пересборке, поэтому прежнее разрешение может не относиться к новому бинарнику. Это подтверждённый дефект сборки; конкретная запись TCC не читалась. Объяснение механизма: [Apple Developer Technical Support](https://developer.apple.com/forums/thread/819406).

На Mac найден один существующий действующий сертификат Apple Development. Теперь обе сборки подписываются им. На этапе обновления подписи сертификаты и ключи не создавались, Keychain и TCC не сбрасывались. Проверка на двух различающихся подписанных revisions подтвердила одинаковый designated requirement без привязки к CDHash.

В коде прежний отказ `CGPreflightScreenCaptureAccess()` всегда вызывал `CGRequestScreenCaptureAccess()` и прерывал подключение. Этот путь удалён. После явного подтверждения подключения доступ проверяет ScreenCaptureKit; приложение не выдаёт отрицательный CoreGraphics preflight за отказ SCK и не вызывает отдельный повторный запрос. Проверка проходит до TLS и создания виртуального дисплея. Система macOS по-прежнему контролирует доступ и может показать свой диалог.

Отказ ScreenCaptureKit `userDeclined` указывает точное приложение, которому требуется доступ. Разрешение отдельного METZ Display не распространяется на захват внутри METZ Manager. Ошибки создания дисплея, выбора экрана и H.264-кодировщика больше не называются автоматически проблемой разрешения. [Apple: userDeclined](https://developer.apple.com/documentation/screencapturekit/scstreamerror/userdeclined).

## Приёмка и возврат

Сборки, Manager/Display core checks, четыре теста выбора подписанта, проверка подписей и проверка стабильности requirement прошли. Захват, UI и системный диалог разрешений агент не запускал; фактический результат проверяет пользователь.

После установки полностью выйдите из Manager/Display через Cmd+Q и откройте установленный Manager из Applications. При переходе с ad-hoc на сертификат macOS может потребовать доступ ещё один раз. Если экран подключается из Manager, разрешение нужно именно **METZ Manager**. После выдачи доступа перезапустите приложение, если этого просит macOS, и повторите подключение.

В следующих сборках нужен тот же сертификат. `scripts/sign_mac_app.py` использует единственную существующую действующую identity; если их несколько, нужно явно выбрать её через `METZ_SIGNING_IDENTITY` (SHA-1 сертификата). При отсутствии/неоднозначности сертификата сборка останавливается, без тихого перехода на ad-hoc и без автоматического создания ключей.

Предыдущие Manager0.6.0/Display0.4.0 сохранены приватно для адресного возврата. Полный возврат не запускался. Он восстанавливает прежние приложения с их прежними требованиями подписи; постоянство разрешения при откате не обещается. Исходники предыдущей пачки: `codex/control-expansion-snapshot`. Новые исходники и отчёт сохранены отдельным Git snapshot; текущая ветка и индекс пользователя сохранены.
