# Manager 0.8 / TV Display 0.6: подтверждение, подключение, режимы и звук

10 октября 2026. Прямой запрос пользователя: исправить подтверждение с клавиатуры ТВ, восстанавливать ADB из приложения после закрытия Terminal, добавить максимальное разрешение/60 кадров в секунду и другие режимы, включаемую передачу звука. Установлены **Manager 0.8.0/build12 и TV Display 0.6.0/code12** по прежнему разрешению ставить готовые обновления. Home, HOME и IME в этой пачке не менялись. Отдельный Display на Mac не возвращался; Android Display остаётся необходимым приёмником.

## Подтверждение на ТВ

Подтверждённая ошибка кода: прежний `OnEditorActionListener` только просил фокус кнопки, не скрывая IME и не выполняя действие. Теперь Done/Go/Next и аппаратный Enter закрывают клавиатуру, убирают фокус из поля и вызывают кнопку. DPAD Down закрывает клавиатуру и переводит фокус без выполнения действия. При валидном ключе, поступившем из Manager, подготовка идентификатора также закрывает клавиатуру и фокусирует кнопку. Если подготовка ещё идёт, выводится понятное ожидание.

Для нового ключа галочка открывает **«Доверять этому Mac?»**; окончательное доверие требует локального нажатия положительной кнопки. Она получает фокус, повторные события не создают второй диалог. При уходе Activity диалог закрывается. Сохранённый ключ использует прежнее одноразовое доверие; внешний intent не заменяет trust anchor. Реальное поведение установленной ТВ-клавиатуры ещё не проверено пользователем.

## Подключение без Terminal

В верхней панели Manager добавлены поле `IP ТВ:порт` и **«Подключиться к ТВ»**. Порт по умолчанию 5555. Адрес IPv4 проверяется и сохраняется локально; при отсутствии нового сохранения используется прежний адрес Display. Кнопка читает `adb devices -l`, при необходимости выполняет `adb connect` и повторно читает состояние. Успех определяется наличием выбранного адреса в состоянии `device`, а не строкой «connected». `unauthorized` требует штатного согласия на ТВ. После ошибки следующая попытка разрешена через минуту, автоматического цикла повторов нет.

«Подключить второй экран» также восстанавливает недоступное ADB-соединение по сохранённому адресу, затем запускает прежний защищённый запрос приёмника. Доступные режимы перечитываются перед передачей. ADB вызывается из существующего абсолютного пути через `Process` без shell/Terminal. Общие `kill-server`, `tcpip`, смена ключей и сброс авторизации не используются. Причина исчезновения ADB именно при закрытии Terminal не установлена; исправлена отсутствовавшая в Manager возможность восстановить соединение.

## Разрешение и частота

Вместо фиксированного 720p/30 выбранные размеры и FPS проходят через виртуальный экран, проверку независимого экрана, ScreenCaptureKit, аппаратный VideoToolbox, конфигурацию и MediaCodec. Режим меняется после остановки. Максимальное разрешение модели **1366×768** взято из [официальной спецификации METZ](https://metzblue.com/fileadmin/Datasheet/MTC6000/32MTC6000Z_Data__Sheet_EN.pdf); framebuffer Android 1280×720 — отдельный параметр, физическая панель экземпляра непосредственно не измерялась.

Новый `StreamModesReceiver` защищён DUMP, читает метаданные аппаратного AVC без запуска Activity или выделения decoder. Проверяется размер/частота и достаточный Baseline profile/level. На установленном ТВ API заявил все восемь сочетаний:

| Размер | Частоты |
|---|---|
| 1366×768 | 30 / 60 |
| 1280×720 | 30 / 60 |
| 960×540 | 30 / 60 |
| 854×480 | 30 / 60 |

При первом чтении выбирается максимальный режим 1366×768/60; следующий выбранный режим сохраняется. Mac metadata query `VTCopySupportedPropertyDictionaryForEncoder` для 1366×768 с требованием hardware encoder завершился `noErr` и перечислил Baseline4.2. Захват, private display API и кодирование кадров при этой проверке не запускались.

[Android VideoCapabilities](https://developer.android.com/reference/android/media/MediaCodecInfo.VideoCapabilities) описывает проверку допустимых размеров/частот. Метаданные **не доказывают устойчивые 60 кадров/с на панели**. Сохраняются один compressed кадр до decoder admission ACK, latest raw кадр и ограниченные deadlines; на медленном ТВ промежуточные raw кадры заменяются до кодирования. Для снижения нагрузки можно выбрать 720p/30. Полный видеотракт и повышение нагрузки максимального режима пока не измерены.

## Звук

Добавлен переключатель **«Транслировать звук Mac на ТВ»**, по умолчанию выключенный. При включении ScreenCaptureKit захватывает системное аудио приложений, без микрофона, 48 кГц/stereo. Float32 преобразуется в little-endian PCM16; пакеты идут в том же канале взаимного pinned TLS. У PCM нет отдельного encoder/codec и зависимости, поток занимает около1,54Мбит/с дополнительно к видео. Настройки захвата описаны в [документации Apple](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos).

На Mac допускается одна аудиопередача размером до8192байт, без растущей очереди и без удержания video credit. При перегрузке сырые аудиосэмплы пропускаются. ТВ создаёт AudioTrack только при включённом звуке; [WRITE_NON_BLOCKING](https://developer.android.com/reference/android/media/AudioTrack) не блокирует видеочтение при заполнении звукового буфера. Буфер порядка80мс или аппаратного минимума, не увеличивается при перегрузке. AudioTrack освобождается при остановке и защищён от гонки stop/configure/write. Ошибка аудиовыхода имеет отдельное сообщение с предложением повторить без звука.

Нет службы, boot receiver, alarm, фонового сканирования или постоянного audio worker. Захват/передача/проигрывание создаются только на сеанс и освобождаются при остановке. Android может сохранить кешированный процесс. Фактическое потребление после сеанса не измерено. Звук на Mac не выключается автоматически; одновременное звучание/эхо зависит от его громкости. DRM-контент, звучание, паузы, задержка и синхронизация аудио/видео ещё не проверены; PCM проигрывается по поступлению, точный A/V scheduling не реализован.

## Проверки и возврат

- Manager core/fake ADB: проверка адреса, отсутствие command injection, последовательность `devices → connect → devices`, сохранение прежних проверок — passed, физическое управление не отправлялось.
- Display core: режимы/уровни/сортировка/deduplication, отказ недопустимых режимов, ограничения PCM, прежние decoder ACK и frame drop проверки — passed.
- Native virtual display doubles проверяют выбранные1366×768/60, ошибки и освобождение; настоящий CGVirtualDisplay не создавался.
- TV JVM: уровни/allowlist, PCM bounds/flags, прежние протокол, очередь и доверие — passed; hardware decoder не запускался.
- Native сборка/подпись и strict offline Android localOptimized build/lint — passed; Android0ошибок/7предупреждений. Новые зависимости и инструменты не устанавливались.
- После установки: версии, прежние APK certificate и designated requirement Mac, data inode, HOME, IME, доступность адресного ADB и metadata receiver проверены. Отдельного Mac Display в Applications нет.

UI/IME/реальный reconnect после закрытия Terminal, создание экрана, курсор/окно, video60/audio/TLS и завершение пользовательского сеанса **не запускались агентом**. Сборка и метаданные не считаются ручной приёмкой.

Прежние Manager0.7/receiver0.5, исходники до/после, установленные APK и очищенные результаты хранятся приватно в игнорируемом `local/display-controls.noindex/`. Точный возврат: остановить сеанс/закрыть Manager, адресно установить подготовленный `receiver-rollback.apk` через `adb -s <проверенный target> install -r`, вернуть `installed-manager-before.app` в Applications, предварительно архивировав текущий Manager в `.noindex`, затем проверить подпись/версию/HOME/IME/data. Rollback содержит прежний TV0.5 с **code13**, прежним сертификатом и без удаления данных; последующее обновление после этого возврата должно иметь code выше13. Mac executable в backup сохранён исполняемым, подпись повторно проверена. Полный возврат этой пачки не запускался.

## Ручная приёмка и этап13

1. Cmd+Q и повторное открытие установленного Manager0.8. В верхней панели проверить сохранённый адрес, закрыть Terminal и нажать «Подключиться к ТВ»; статус должен стать «Подключён».
2. В «Экран» проверить1366×768/60 и начать со звуком выключенным. Для нового ключа галочка должна открыть диалог доверия; подтвердить его на ТВ, затем подключиться из Manager.
3. Переместить курсор и окно. Если есть обрыв, записать точный текст; попробовать720p/30 для сравнения.
4. Остановить, включить звук, подключиться и проиграть обычный незашифрованный ролик/системный звук. Проверить звучание/задержку, затем остановку и повторный запуск из Home.

Доработка текущего этапа13 установлена; сам этап остаётся активным до этих ручных результатов. Следующая цель — подтвердить стабильность/60FPS/звук/ресурсы после остановки и оставшуюся приёмку standby. Новый этап не добавлен.
