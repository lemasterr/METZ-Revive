# Manager 0.9.1: компактный интерфейс, подключение и повторный экран

10 октября 2026. Установлены **Manager 0.9.1 / build 15** и **TV Display 0.7.0 / code 16**. Общий этап 13 остаётся активным: короткие проверки не заменяют длительную ручную приёмку.

## Изменения и причины

- Холодный собственный ADB helper ещё не знает ТВ, даже если Terminal ранее подключался. Проверка питания теперь сначала подключает сохранённый адрес по действию пользователя; состояние без проверки не выдаётся за выключение.
- Ответ `dumpsys power` на устройстве превышает 225 КБ. Прежний предел 64 КБ отклонял полный ответ как обрезанный. По уточнению пользователя Manager принимает до **1 МиБ stdout и 1 МиБ stderr** для команд ТВ; запрос не урезан на устройстве. Превышение предела и timeout по-прежнему считаются ошибкой. Общие малые команды сохраняют предел 64 КиБ.
- macOS возвращала Local Network denied при включённом переключателе. По конкретному согласию обновлено только разрешение Manager через off → on. Для итоговой подписанной версии обычный GUI и повторный запуск подтвердили ADB и `Awake`. Причина устаревшего состояния разрешения macOS не установлена; защита не обходилась.
- Остановка ждёт завершения захвата и очереди транспорта, инвалидирует VideoToolbox, очищает raw pending кадры и телеметрию, удаляет только собственный виртуальный экран. Следующий запуск блокируется до окончания очистки. На ТВ следующий сеанс ждёт освобождения прежнего декодера; зависший decoder не используется повторно. Старые callbacks отсекаются поколением сеанса.
- Admission ACK выдаётся сразу после `MediaCodec.queueInputBuffer`, до drain output. Добавлены отдельные счётчики захвата, приёма, выхода декодера и доступных render callbacks. Телеметрия включается конфигурацией нового клиента; старым клиентам неизвестные сообщения не отправляются.
- Интерфейс следует пользовательскому [ZIP v2](design/metz-manager-ui/SKILL.md). После ручного отзыва пользователя уменьшены D-pad до 200 pt и обычные кнопки до 34 pt, выровнены ряды, действия перенесены справа, снято ограничение ширины основного содержимого, убраны повторяющиеся подписи. Стиль сохранён. Итоговую визуальную приёмку проводит пользователь; агент не объявляет её пройденной.

## Реальный тест экрана

Разрешённый пользователем тест: два сеанса **1366×768 / target 60**, собственный виртуальный экран, сгенерированная движущаяся полоса, системный звук выключен. Прогрев 3 секунды, затем восемь секунд замера. Для обоих сеансов подтверждены выбранный Quartz mode, окно на собственном дисплее и декодирование на ТВ.

| Сеанс | Секунд | Захват Mac FPS | Admission FPS | Выход декодера FPS | Surface FPS |
| --- | --- | --- | --- | --- | --- |
| 1 | 8.05 | 57.61 | 57.61 | 57.64 | нет данных |
| 2 | 8.04 | 56.61 | 56.61 | 56.51 | нет данных |

После обеих остановок active=false, все проверенные ресурсы сеанса освобождены, собственный дисплей отсутствует. В отдельном чтении списка потоков кешированного процесса ТВ не осталось metz-receiver/metz-decoder/metz-idr. Сам Manager и системный кеш процесса Android не уничтожаются. Постоянного listener/service/опроса нет.

**60 FPS настроены, но устойчивые 60 FPS не доказаны.** Короткий итоговый замер передачи — 56–58 FPS. Другой промежуточный запуск давал около 47–49 FPS выхода декодера, поэтому скорость варьируется и длинная нагрузка требует отдельной приёмки. Отсутствующие render callbacks на Android 11 означают отсутствие измерения Surface, а не нулевую частоту. Выход декодера не доказывает физическую частоту панели.

Первый диагностический stimulus на Core Animation не создавал непрерывных изменений; его нули исключены из FPS-вывода. Ошибка владения NSWindow в первом test harness устранена. Это отдельные ошибки диагностического сценария; они не объявлены доказанной причиной пользовательских лагов.

## Настройка ТВ и браузер

По прямому запросу `system.screen_off_timeout` изменён с 1800000 на **3600000 мс (1 час)** и проверен чтением. `secure.sleep_timeout=10800000` и screensaver_enabled=0 сохранены. Физическое ожидание одного часа не проводилось.

Последнее уточнение пользователя заменило первоначальный выбор No BS: установлен **[Mrowser 1.3.0 / code 8](https://github.com/m-salehi-v/mrowser/releases/tag/v1.3.0)** из официального GitHub release. Размер APK 4852471 байт, SHA-256 сопоставлен с digest GitHub, APK signature проверена; minSdk23 подходит устройству. Это проверка происхождения и целостности, не функциональная приёмка браузера.

**TV Bro и No BS TV Browser удалены только для user 0 с `-k`**. Их данные и точные APK сохранены приватно для возврата. Штатный WebView, Kick, HOME, IME, ADB и Cast сохранены. UI Mrowser агентом не запускался.

## Проверки и возврат

Manager core/fake ADB/owned-helper fixtures, Mac protocol/virtual-display doubles, TV JVM protocol, Home JVM catalog, Python suite, offline Android builds/lint и подписи прошли. Два устаревших Home preview assertions обновлены под уже реализованные защищённые DUMP receivers и BIND_INPUT_METHOD; проверка отсутствия сетевых разрешений/неразрешённых фоновых компонентов сохранена.

Предыдущие Manager 0.8.1 и receiver 0.6.1/code14, новые промежуточные bundles, source snapshots и подписанный receiver rollback **0.6.1/code17** сохранены в игнорируемом `local/manager-ui-stream.noindex`. APK возврата имеет ту же подпись и больший versionCode; после применения возврата следующее обновление требует code>17. Установки сохранили inode данных TV Display, HOME и IME. Полный возврат пары не запускался.

Возврат таймера: `settings put system screen_off_timeout 1800000` через адресный ADB. Возврат браузеров: `cmd package install-existing --user 0 PACKAGE` для сохранённых пакетов, при необходимости установка соответствующего сохранённого APK. Доступность пакетов и сохранённых данных проверяется после возврата; история сайтов не гарантируется без ручной приёмки. Удалять Mrowser при возврате — отдельное решение.

Следующий шаг: пользовательская проверка итоговой плотности интерфейса, Mrowser и длительного использования экрана. Звук, сон/пробуждение, быстрый курсор и разные разрешения остаются отдельными непроверенными сценариями. Raw logs, изображения, APK, адреса и ключи в Git не входят.
