# Финальная доработка Home, Manager и Display

Обновление10 октября: [Home0.6 / Manager0.5 / Display0.3 установлены, default HOME сменён, stock обратимо отключён](USABILITY_REFINEMENT.md). Этот документ сохраняет историю предыдущей пачки0.5/0.4/0.2.

9–10 октября 2026. Источник — прямое поручение пользователя и два приложенных изображения. Home0.5 и TV Display0.2 установлены после отдельного подтверждения; Manager0.4 и резервный Mac Display0.2 скопированы в Applications пользователя. Данные/default HOME/текущая клавиатура и защищённые состояния пакетов сохранены. Отдельно подтверждены и применены отключение заставки и idle30мин. UI/runtime/скорость пользователь проверяет сам.

## Заставка, сон и launcher

Подтверждено read-only: `Dreaming`, штатный Backdrop, заставка включена; `screen_off_timeout=300000` (5 минут), `sleep_timeout=10800000` (3 часа). Это не доказательство выгрузки приложений заставкой. У Android [LMKD](https://source.android.com/docs/core/perf/lmkd) может освобождать малозначимые процессы при нехватке памяти; на этом ТВ конкретный источник повторной загрузки после сна ещё не установлен.

В [PowerManagerService Android 11](https://android.googlesource.com/platform/frameworks/base/+/android-11.0.0_r1/services/core/java/com/android/server/power/PowerManagerService.java) запуск dream и переход в сон связаны с idle timeout. OEM может менять поведение. Простое выключение заставки не гарантирует сохранение процессов и может раньше переводить ТВ в сон.

Отдельная пачка подтверждена пользователем и применена: `secure/screensaver_enabled` 1 → 0, `system/screen_off_timeout` 300000 → 1800000 (30 минут). Значения перечитаны; `sleep_timeout=10800000` (3 часа) сохранён. Ручной standby не переопределён. Откат — вернуть точные исходные 1/300000. Выигрыш RAM/скорости не измерен; панель будет дольше оставаться активной. Системный Backdrop не удалён.

В финальном чтении wakefulness=Awake; процесс Backdrop ещё присутствует. Отключение автоматической заставки не равно выгрузке её кешированного процесса. Причина сохранения/приоритет процесса и экономия RAM не измерены; принудительное завершение/отключение пакета не выполнялось. `/proc/stat` доступен на текущем ТВ — источник нового CPU-показателя реально читается, но кнопки Manager пока не проверены.

Новый default HOME выбирает launcher для кнопки Home, но не отключает прежний пакет и его компоненты. После устойчивой ручной приёмки можно адресно отключить `com.google.android.tvlauncher`, сохранив APK/данные/возможность ADB возврата. Recommendations уже отключён; повторять не нужно. Точная экономия RAM старого launcher неизвестна. Anoki сохранён: прежний опыт отключения не подтвердил пользу.

## Проверки и возврат

- Home и receiver: strict offline localOptimized assemble/JVM checks/lint прошли. Home: 0 ошибок/14 предупреждений; receiver: 0 ошибок/7 предупреждений. Предупреждения target/API, backup, прежних неиспользованных ресурсов/локализации и проверяемого pinned trust manager сохранены, не скрыты.
- Manager: native build, core tests, fake ADB persistent-channel test, parsing/Unicode fingerprint/CPU reset-overflow checks прошли. Это проверка процесса на Mac с заглушкой ADB, не кнопок ТВ.
- Mac Display: native build/core/codesign; private API/capture не запускались.
- APK подписи совпали с установленными; manifest новых сборок `debuggable=false`, R8/resource shrink включены. Home 60 544 Б, receiver 54 376 Б. Размер APK не равен памяти процесса или latency.
- Установка новой пачки подтверждена человеком и выполнена; версии/data inode/default HOME/выбранный IME и защищённые package overrides проверены. Mac приложения подписаны и не запускались.
- До изменений сохранены установленные APK и package/HOME/IME/settings state в игнорируемом приватном `local/final-refinement/`.
- Собраны старые исходники как rollback APK с версиями code5/code3 и прежней подписью: установка `-r` без downgrade/удаления данных. Сам возврат этой новой пачки не испытан. Исходные APK дополнительно сохранены; их downgrade после nondebuggable обновления не гарантируется.
- UI/screenshots/input injection/Unicode/сопряжение/TLS/самостоятельный desktop/standby пока не проверены агентом. Пользователь ранее выбрал проверять UI/runtime сам.

## Ручная приёмка

1. Home: Приложения → вторая страница → назад; поиск; удержание OK → добавить/убрать/переместить; общий список избранного; Display виден и запускается.
2. Manager: быстрый пульт сначала первый запуск, затем серия стрелок/OK/Back; резервный канал при отказе. Записать ощущаемую задержку; число доставки не заменяет наблюдение экрана.
3. Клавиатура: подтвердить включение → открыть поле поиска на ТВ → отправить `Привет METZ`/символы → удалить → поиск; вернуть прежний IME, проверить обычный ввод. Пароли/платёжные поля не нужны для проверки.
4. Приложения/диагностика: реальные названия/иконки, запуск, обновление RAM/CPU/хранилища; unknown при недоступном чтении.
5. Экран: подготовить ключи → подтвердить доверие ТВ → «Принимать» → подключить в Manager → перенести окно → остановить; проверить курсор, читаемость, возврат окна, отсутствие оставшегося виртуального дисплея.
6. После естественного ожидания/standby: скорость открытия Home/приложений, связь пульта, звук. Не проводить повторные перезагрузки/стресс-тест ради этой приёмки.

После неё: выбрать METZ Home default с включённым stock, проверить Home/сон/ADB; только затем решать отключение старого launcher. Завершение этапов 7/9/12/13 зависит от реальной приёмки, а не только успешной сборки.
