# METZ Revive

Исследование и аккуратная модернизация METZ 32MTC6000Z: меньше лишней нагрузки, стабильное видео и звук, безопасный откат. Репозиторий содержит диагностику физического телевизора и журнал согласованных изменений.

## Текущее состояние — 9 октября 2026

- Android 11 / API 30, платформа `m5621`, 4 × Cortex-A53 до 1,3 ГГц, GPU Mali-470 MP.
- Android видит 929 000 КиБ RAM (907,2 МиБ), zRAM около 500 МиБ. Точная установленная физическая RAM и коммерческое обозначение SoC пока не подтверждены.
- Framebuffer Android: 1280×720, 60 Гц. Панель по официальной спецификации: 1366×768.
- Главный подтверждённый ресурсный предел — небольшой объём RAM: первоначальный `meminfo` имел статус `critical`; позднейшие срезы отличаются. Постоянная перегрузка CPU не доказана.
- Уточнён дефект `mtktvapi.agent`: три падения из-за отсутствующего класса громкости, зарегистрированный vendor JAR отсутствует по указанному пути, APK не содержит класс и не подключает библиотеку. Связь с хрипом не доказана.
- Пользователь вновь подтвердил нормальный звук; задержки бывают именно при управлении через atvTools с телефона. Накопленная статистика HOME показывает jank, но причина телефонных задержек ещё не локализована.
- По отдельному согласию удалён TCL Browser для user 0 с флагом сохранения данных (`-k`); исходные три APK сохранены приватно для возврата. Данные не экспортировались, возврат ещё не испытан. Kick сохранён.
- Установлен TV Bro 2.1.6 без Gecko из официального релиза: 6,79 МБ, API 24+, поддержка `armeabi-v7a`. Проверены SHA-256, подпись, версия установленного пакета и Leanback resolver. Штатный HOME и atvTools сохранены. Пользователь сообщил о выполненной ручной проверке; подробности сайтов/видео и замеры скорости не предоставлены.
- Применена обратимая пачка Recommendations/Anoki. Recommendations отключён (процесс и служба остановились); Anoki возвращён в исходный режим, поскольку persistent-процесс продолжал работать. Возврат обоих пакетов проверен на ТВ; функциональная оценка HOME и прирост скорости ещё не подтверждены.

## Снимки по запросу

Нужны уже установленные Python 3.9+ и ADB. Зависимости не требуются. Сначала проверить подключение и выбрать ровно нужное устройство; не сохранять его адрес в публичных конфигурациях.

```sh
adb devices -l
python3 scripts/collect_diagnostics.py --serial '<текущее устройство из adb devices>' --profile audio --label distorted-audio
```

Профили: `baseline` — исходное состояние, `audio` — звук, `video` — воспроизведение, `remote` — телефонные задержки (ввод, Wi-Fi, helper, HOME framestats). Скрипт только читает, не подключает и не перезагружает ТВ. Проверяет авторизацию до сбора, выполняет команды последовательно; предел одной команды 20 секунд, сохраняемого вывода — 256 КиБ на поток. Код возврата shell может относиться только к последней команде: обязательно учитывать `stderr`, `timed_out` и `truncated`.

Raw-результаты могут содержать приватные данные. Они остаются в игнорируемом `local/diagnostics/`; существующие снимки не перезаписываются. Разные условия сравнивать под разными метками. Снимок аудио желательно собрать во время естественного появления хрипа до изменения состояния устройства.

## Локальная проверка

```sh
python3 -m unittest discover -s tests -v
git diff --check
```

Тесты используют локальные процессы и подмену ADB; не управляют ТВ и не запускают UI. Проигрывание Twitch/Cast, задержка клавиш и выход из standby автоматически не проверялись. Сценарии следующего наблюдения приведены в диагностическом отчёте.
